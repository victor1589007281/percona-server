# Change Buffer
## 用来解决什么问题？

解决二级索引的随机IO问题：
1. 回表查询产生随机IO
2. 二级索引记录分散在不同磁盘非连续位置中
3. DML写入放大

## 怎么解决的？
将二级索引的变更操作缓冲在内存中，延迟合并到磁盘，将随机写转换为顺序写
## 谁来管理？
### 1. 工作流程
#### 1.1 写入阶段：
当修改二级索引时：
1. 检查目标页是否在缓冲池中
2. 如果不在，则将变更记录到Change Buffer
3. 只在内存中记录变更，不立即写入磁盘
#### 1.2 合并过程
1. 将Change Buffer中的变更加载到内存
2. 应用所有缓冲的变更到索引页
3. 将更新后的页标记为脏页
4. 后续由刷脏机制写入磁盘
Note:
- **合并触发条件**：
  - 读取需要该索引页时（被动合并）
  - Change Buffer空间不足时（主动合并）
  - 后台线程定期扫描合并
  - 实例正常关闭时
- **连续修改处理**：
  - 同页的多次修改会追加到操作链
  - 通过`ibuf_insert_low()`函数管理操作链
- **强制合并阈值**
  - 操作链长度超过`IBUF_MAX_N_PAGES_MERGED`(默认8)会触发强制合并
  - 单个页的Change Buffer记录超过`IBUF_PAGE_SIZE_PER_FREE_SPACE`(默认4KB)也会触发
### 2.持久化与故障恢复
- **Redo日志**：所有Change Buffer修改都记录redo（ibuf bitmap和操作记录）
- **故障恢复**：
  - 通过redo恢复Change Buffer结构
  - 重启后按需合并未完成的变更
- **空间不足处理**：
  - 优先淘汰冷数据页
  - 最终会写入系统表空间(ibdata1)的ibuf segment
