# MySQL 存储架构分析与分布式块存储元数据管理设计

> 版本: 1.0
> 日期: 2026-02-05
>
> 本文档深入分析 MySQL/InnoDB 的核心存储文件（Redo Log、IBD、Double Write、Binlog）的物理组织结构，
> 并设计一个中间元数据管理层，使 MySQL 能够运行在无文件系统的分布式块存储设备上，
> 实现类似 Aurora 的存算分离架构。

## 2. Redo Log 文件结构详解

### 2.1 Redo Log 文件整体结构

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Redo Log 文件物理结构 (MySQL 8.0.30+)                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │                    单个 Redo Log 文件结构                             │  │
│  │                                                                       │  │
│  │  文件: #ib_redoN (N = 0, 1, 2, ... 最多32个)                         │  │
│  │  默认大小: innodb_redo_log_capacity / 32                              │  │
│  │                                                                       │  │
│  │  ┌─────────────────────────────────────────────────────────────────┐ │  │
│  │  │ Offset 0x0000                                                    │ │  │
│  │  │ ┌─────────────────────────────────────────────────────────────┐ │ │  │
│  │  │ │              LOG FILE HEADER (2048 bytes = 4 blocks)        │ │ │  │
│  │  │ │                                                              │ │ │  │
│  │  │ │  Block 0 (512B): File Header                                │ │ │  │
│  │  │ │  Block 1 (512B): Checkpoint 1                               │ │ │  │
│  │  │ │  Block 2 (512B): Encryption Info                            │ │ │  │
│  │  │ │  Block 3 (512B): Checkpoint 2                               │ │ │  │
│  │  │ └─────────────────────────────────────────────────────────────┘ │ │  │
│  │  │ Offset 0x0800 (2048)                                            │ │  │
│  │  │ ┌─────────────────────────────────────────────────────────────┐ │ │  │
│  │  │ │                                                              │ │ │  │
│  │  │ │              LOG BLOCKS (日志块序列)                         │ │ │  │
│  │  │ │                                                              │ │ │  │
│  │  │ │  每个块 512 字节 (OS_FILE_LOG_BLOCK_SIZE)                   │ │ │  │
│  │  │ │  Block N, Block N+1, Block N+2, ...                         │ │ │  │
│  │  │ │                                                              │ │ │  │
│  │  │ └─────────────────────────────────────────────────────────────┘ │ │  │
│  │  │ Offset: 文件末尾                                                │ │  │
│  │  └─────────────────────────────────────────────────────────────────┘ │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  关键常量 (来自 log0constants.h):                                           │
│  • OS_FILE_LOG_BLOCK_SIZE = 512 字节                                       │
│  • LOG_FILE_HDR_SIZE = 4 * 512 = 2048 字节                                 │
│  • LOG_BLOCK_HDR_SIZE = 12 字节                                            │
│  • LOG_BLOCK_TRL_SIZE = 4 字节 (checksum)                                  │
│  • LOG_BLOCK_DATA_SIZE = 512 - 12 - 4 = 496 字节                           │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

│  │  │                                                                  ││  │
│  │  │  处理:                                                           ││  │
│  │  │  1. 将 Redo 写入 Redo Log Store                                 ││  │
│  │  │  2. 复制到多个副本 (quorum write)                               ││  │
│  │  │  3. 更新 received_lsn 和 durable_lsn                            ││  │
│  │  │  4. 返回确认                                                     ││  │
│  │  │                                                                  ││  │
│  │  │  响应: WriteRedoResponse(durable_lsn)                            ││  │
│  │  └─────────────────────────────────────────────────────────────────┘│  │
│  │                                                                       │  │
│  │  2. Read Page (Reader/Writer Node 调用)                              │  │
│  │  ───────────────────────────────                                     │  │
│  │  ┌─────────────────────────────────────────────────────────────────┐│  │
│  │  │  请求: ReadPage(space_id, page_no, min_lsn)                     ││  │
│  │  │                                                                  ││  │
│  │  │  处理:                                                           ││  │
│  │  │  1. 查找 Page Store 中的页                                      ││  │
│  │  │  2. 如果 page.lsn < min_lsn:                                    ││  │
│  │  │     - 从 Redo Log Store 获取 [page.lsn, min_lsn] 的 redo        ││  │
│  │  │     - 应用 redo 到页 (重建最新版本)                             ││  │
│  │  │  3. 返回页数据                                                   ││  │
│  │  │                                                                  ││  │
│  │  │  响应: ReadPageResponse(page_data, page_lsn)                     ││  │
│  │  └─────────────────────────────────────────────────────────────────┘│  │
│  │                                                                       │  │
│  │  3. Background Apply (存储层内部)                                    │  │
│  │  ───────────────────────────────                                     │  │
│  │  ┌─────────────────────────────────────────────────────────────────┐│  │
│  │  │  后台任务: 持续将 Redo 应用到数据页                             ││  │
│  │  │                                                                  ││  │
│  │  │  while (true) {                                                  ││  │
│  │  │      // 获取未应用的 Redo 记录                                  ││  │
│  │  │      records = get_unapplied_redo(applied_lsn, durable_lsn);    ││  │
│  │  │                                                                  ││  │
│  │  │      for (record in records) {                                   ││  │
│  │  │          page = read_page_from_store(record.space_id,            ││  │
│  │  │                                      record.page_no);            ││  │
│  │  │          apply_redo(page, record);                               ││  │
│  │  │          write_page_to_store(page);                              ││  │
│  │  │      }                                                           ││  │
│  │  │                                                                  ││  │
│  │  │      applied_lsn = max_applied_lsn;                              ││  │
│  │  │      sleep(interval);                                            ││  │
│  │  │  }                                                               ││  │
│  │  └─────────────────────────────────────────────────────────────────┘│  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 8.4 计算层修改

┌─────────────────────────────────────────────────────────────────────────────┐

│  │                                                                       │  │
│  │  1. Redo Log 写入                                                     │  │
│  │  ─────────────────                                                   │  │
│  │  原: 写入本地 redo log 文件                                          │  │
│  │  改: 发送到存储层 (WriteRedo RPC)                                    │  │

│  │  void log_writer() {                                                  │  │
│  │  #ifdef AURORA_MODE                                                   │  │
│  │      // 发送 Redo 到存储层                                           │  │
│  │      storage_client->write_redo(redo_buffer, start_lsn, end_lsn);    │  │
│  │  #else                                                                │  │
│  │      // 原有: 写入本地文件                                           │  │
│  │      os_file_write(redo_file, redo_buffer, offset);                  │  │
│  │  #endif                                                               │  │
│  │  }                                                                    │  │
│  │                                                                       │  │
│  │  2. Page 读取                                                         │  │
│  │  ─────────────                                                       │  │
│  │  原: 从本地 IBD 文件读取                                             │  │
│  │  改: 从存储层读取 (ReadPage RPC)                                     │  │
│  │                                                                       │  │
│  │  // buf0flu.cc, buf0rea.cc                                           │  │
│  │  buf_page_t* buf_page_get() {                                         │  │
│  │  #ifdef AURORA_MODE                                                   │  │
│  │      // 从存储层读取，传入需要的最小 LSN                             │  │
│  │      page = storage_client->read_page(space_id, page_no, min_lsn);   │  │
│  │  #else                                                                │  │
│  │      // 原有: 从本地文件读取                                         │  │
│  │      os_file_read(ibd_file, page, offset);                           │  │
│  │  #endif                                                               │  │
│  │  }                                                                    │  │
│  │                                                                       │  │
│  │  3. 禁用 Double Write                                                 │  │
│  │  ──────────────────────                                              │  │

│  │  改: 存储层保证原子性，无需 DBLWR                                    │  │

│  │  // buf0dblwr.cc                                                      │  │
│  │  #ifdef AURORA_MODE                                                   │  │
│  │  // 完全禁用 Double Write                                            │  │
│  │  innodb_doublewrite = false;                                          │  │
│  │  #endif                                                               │  │
│  │                                                                       │  │
│  │  4. 禁用脏页刷盘                                                      │  │
│  │  ──────────────────                                                  │  │
│  │  原: Page Cleaner 后台刷脏                                           │  │
│  │  改: 不刷盘！存储层负责应用 Redo                                     │  │
│  │                                                                       │  │
│  │  // buf0flu.cc                                                        │  │
│  │  #ifdef AURORA_MODE                                                   │  │
│  │  void buf_flush_page() {                                              │  │
│  │      // 不写入 IBD 文件                                              │  │
│  │      // 只是从 Buffer Pool 移除                                      │  │
│  │      buf_page_free(page);                                             │  │
│  │  }                                                                    │  │
│  │  #endif                                                               │  │
│  │                                                                       │  │
│  │  5. 禁用 Checkpoint 写数据页                                          │  │
│  │  ──────────────────────────────                                      │  │
│  │  原: Checkpoint 时刷所有脏页                                         │  │
│  │  改: Checkpoint 只记录 LSN，不刷页                                   │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

#### 8.7.1 业界方案分析

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Aurora / PolarDB DDL 处理方案对比                         │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │  AWS Aurora 方案                                                      │  │
│  │  ──────────────────────────────────────────────────────────────────  │  │
│  │                                                                       │  │
│  │  1. Atomic DDL (MySQL 8.0):                                          │  │
│  │     - 元数据存储在 InnoDB 事务表中                                   │  │
│  │     - DDL 本身是 ACID 的                                             │  │
│  │     - 但 DDL 期间仍需获取 MDL (Metadata Lock)                        │  │
│  │                                                                       │  │
│  │  2. 读一致性级别:                                                    │  │
│  │     - EVENTUAL: 不等待复制，可能读到旧数据                           │  │
│  │     - SESSION:  同一会话内可见自己的修改                             │  │
│  │     - GLOBAL:   等待所有修改可见                                     │  │
│  │                                                                       │  │
│  │  3. 问题:                                                            │  │
│  │     - DDL 期间 RO 的相关表查询会阻塞或报错                           │  │
│  │     - Apply 冲突会严重增加复制延迟                                   │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │  PolarDB 方案 (更先进)                                                │  │
│  │  ──────────────────────────────────────────────────────────────────  │  │
│  │                                                                       │  │
│  │  1. 异步 MDL 复制 (Async MDL Replication):                           │  │
│  │     ┌─────────────────────────────────────────────────────────────┐ │  │
│  │     │                                                              │ │  │
│  │     │  传统方式:                                                   │ │  │
│  │     │  ┌─────────────────────────────────────────────────────────┐│ │  │
│  │     │  │ Main Apply Process                                       ││ │  │
│  │     │  │ ──────────────────                                       ││ │  │
│  │     │  │ Apply Redo ──► 遇到 DDL Lock ──► 阻塞等待 ──► 超时      ││ │  │
│  │     │  │                                   (最多30秒)              ││ │  │
│  │     │  │                                                          ││ │  │
│  │     │  │ 问题: DDL 阻塞整个 apply 进程，影响所有表！              ││ │  │
│  │     │  └─────────────────────────────────────────────────────────┘│ │  │
│  │     │                                                              │ │  │
│  │     │  PolarDB 优化:                                               │ │  │
│  │     │  ┌─────────────────────────────────────────────────────────┐│ │  │
│  │     │  │ Main Apply Process          Lock Apply Process          ││ │  │
│  │     │  │ ──────────────────          ──────────────────          ││ │  │
│  │     │  │ Apply Redo ──► 遇到 DDL ──► 分发到独立进程 ──► 继续     ││ │  │
│  │     │  │              │                    │                      ││ │  │
│  │     │  │              │                    ▼                      ││ │  │
│  │     │  │              │              异步等待获取锁                ││ │  │
│  │     │  │              │              (不影响主进程)                ││ │  │
│  │     │  │              │                                           ││ │  │
│  │     │  │ 优势: 其他表的 Redo 可以继续 apply！                     ││ │  │
│  │     │  └─────────────────────────────────────────────────────────┘│ │  │
│  │     │                                                              │ │  │
│  │     └─────────────────────────────────────────────────────────────┘ │  │
│  │                                                                       │  │
│  │  2. DDL 锁同步流程:                                                   │  │
│  │     T1: RW 获取本地 DDL 锁                                           │  │
│  │     T2: RW 写锁信息到 Redo/WAL                                       │  │
│  │     T3: RW 等待所有 RO apply 到该 LSN (RO 获取锁)                    │  │
│  │     T4: 所有 RO 获取锁后，RW 执行 DDL                                │  │
│  │     T5: RW 释放锁，写释放信息到 Redo                                 │  │
│  │     T6: RO apply 到释放点，释放锁                                    │  │
│  │                                                                       │  │
│  │  3. 仍存在的问题:                                                    │  │
│  │     - DDL 期间，该表在 RO 上不可查询                                 │  │
│  │     - 如果 RO 有长查询，DDL 可能超时                                 │  │
│  │     - 只是解决了 "不影响其他表"，没有解决 "该表不可用"              │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │  我们的目标: DDL 期间表仍可查询 (Schema MVCC)                        │  │
│  │  ──────────────────────────────────────────────────────────────────  │  │
│  │                                                                       │  │
│  │  - RO 正在执行的查询看到旧 schema                                    │  │
│  │  - 新查询可以选择看新 schema 或等待                                  │  │
│  │  - 不阻塞任何操作                                                    │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

#### 8.7.2 新方案: Schema MVCC (多版本 Schema)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Schema MVCC 核心设计                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  核心思想: 像数据 MVCC 一样，对 Schema 也实现多版本并发控制                  │

│                                                                             │

│  │  ─────────────────────          ─────────────────────                │  │
│  │  • 每行有版本 (trx_id)          • 每表空间有版本 (schema_version)   │  │

│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐  │

│  │  ──────────────────────────────────────────────────────────────────  │  │
│  │                                                                       │  │

│  │      // 表结构元数据                                                  │  │
│  │      ColumnDef columns[];                                             │  │
│  │      IndexDef  indexes[];                                             │  │

│  │                                                                       │  │

#### 8.7.3 Schema Snapshot 与无阻塞查询

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Schema Snapshot 机制                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  每个查询/事务在开始时获取一个 Schema Snapshot，整个执行期间使用该快照       │
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │  Schema Snapshot 结构                                                 │  │
│  │  ──────────────────────────────────────────────────────────────────  │  │
│  │                                                                       │  │
│  │  struct SchemaSnapshot {                                              │  │

│  │                                                                       │  │
│  │      // 查询可见的表空间版本缓存                                      │  │
│  │      HashMap<TableName, TablespaceVersion*> visible_tables;          │  │
│  │  };                                                                   │  │
│  │                                                                       │  │
│  │  // 获取 Schema Snapshot                                              │  │
│  │  SchemaSnapshot* get_schema_snapshot(uint64_t lsn) {                  │  │
│  │      SchemaSnapshot* ss = new SchemaSnapshot();                       │  │
│  │      ss->snapshot_lsn = lsn;                                          │  │
│  │      return ss;                                                       │  │
│  │  }                                                                    │  │
│  │                                                                       │  │
│  │  // 根据 snapshot 查找表的可见版本                                    │  │
│  │  TablespaceVersion* find_visible_table(SchemaSnapshot* ss,            │  │
│  │                                        const char* table_name) {      │  │
│  │      // 遍历该表的所有版本，找到 snapshot_lsn 时可见的那个            │  │
│  │      for (v in all_versions_of(table_name)) {                         │  │
│  │          // 可见条件: create_lsn <= snapshot_lsn                     │  │
│  │          //          AND (drop_lsn == 0 OR drop_lsn > snapshot_lsn)  │  │
│  │          if (v->create_lsn <= ss->snapshot_lsn &&                     │  │
│  │              (v->drop_lsn == 0 || v->drop_lsn > ss->snapshot_lsn)) {  │  │
│  │              return v;                                                │  │
│  │          }                                                            │  │
│  │      }                                                                │  │

│                                                                             │

│  │                                                                       │  │
│  │  时间线:                                                              │  │
│  │  ────────────────────────────────────────────────────────────────────│  │
│  │                                                                       │  │
│  │  LSN   1000      1100       1200        1300       1400             │  │

│  │        │          │          │           │          │                │  │
│  │     CREATE t   INSERT    DROP t      CREATE t   INSERT              │  │
│  │    (space=100)  INTO t  (space=100)  (space=101) INTO t             │  │
│  │                                                                       │  │
│  │  查询 Q1 在 LSN=1150 时启动:                                         │  │
│  │  ┌────────────────────────────────────────────────────────────────┐ │  │

│  │  │  看到: table "t" → space_id=101, schema_v=1002                  │ │  │

│  │  │  Q2 看到新版本的表!                                              │ │  │
│  │  └────────────────────────────────────────────────────────────────┘ │  │
│  │                                                                       │  │
│  │  Q1 和 Q2 可以同时执行，互不干扰！                                   │  │

#### 8.7.4 存储层多版本支持

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    存储层多版本支持                                          │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  存储层需要支持同时存储多个版本的表空间数据                                  │
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │  1. 页索引扩展为四元组                                                │  │
│  │  ──────────────────────────────────────────────────────────────────  │  │
│  │                                                                       │  │
│  │  // 原来: (space_id, page_no) → LBA                                  │  │
│  │  // 新增: (space_id, schema_version, page_no) → LBA                  │  │
│  │                                                                       │  │
│  │  struct PageKey {                                                     │  │
│  │      uint32_t space_id;                                               │  │
│  │      uint64_t schema_version;                                         │  │
│  │      uint32_t page_no;                                                │  │
│  │  };                                                                   │  │
│  │                                                                       │  │
│  │  PageIndex: PageKey → (LBA, page_lsn)                                │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │  2. Redo 应用时的版本路由                                             │  │
│  │  ──────────────────────────────────────────────────────────────────  │  │
│  │                                                                       │  │
│  │  // Redo 记录中包含 schema_version                                    │  │
│  │  struct RedoRecord {                                                  │  │
│  │      uint8_t  type;                                                   │  │
│  │      uint32_t space_id;                                               │  │
│  │      uint64_t schema_version;    // 目标 schema 版本                 │  │
│  │      uint32_t page_no;                                                │  │
│  │      bytes    body;                                                   │  │
│  │  };                                                                   │  │
│  │                                                                       │  │
│  │  // 存储层应用 Redo                                                   │  │
│  │  void apply_redo(RedoRecord* rec) {                                   │  │
│  │      PageKey key = {rec->space_id, rec->schema_version, rec->page_no};│  │
│  │                                                                       │  │
│  │      // 检查该 schema version 是否仍活跃                              │  │
│  │      if (!is_schema_version_active(rec->space_id, rec->schema_version))│ │
│  │      {                                                                │  │
│  │          // 该版本已被 GC，跳过                                       │  │
│  │          return;                                                      │  │
│  │      }                                                                │  │
│  │                                                                       │  │
│  │      // 读取或创建页                                                  │  │
│  │      Page* page = get_or_create_page(key);                            │  │
│  │      apply_redo_to_page(page, rec);                                   │  │
│  │      write_page(key, page);                                           │  │
│  │  }                                                                    │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │  3. 读取页时的版本选择                                                │  │
│  │  ──────────────────────────────────────────────────────────────────  │  │
│  │                                                                       │  │
│  │  message ReadPageRequest {                                            │  │
│  │      uint64 db_id = 1;                                                │  │
│  │      uint32 space_id = 2;                                             │  │
│  │      uint64 schema_version = 3;  // 指定要读取的 schema 版本         │  │
│  │      uint32 page_no = 4;                                              │  │
│  │      uint64 min_lsn = 5;         // 需要的最小 LSN                   │  │
│  │  }                                                                    │  │
│  │                                                                       │  │
│  │  // 读取逻辑                                                          │  │
│  │  Page* read_page(ReadPageRequest* req) {                              │  │
│  │      PageKey key = {req->space_id, req->schema_version, req->page_no};│  │
│  │                                                                       │  │
│  │      Page* page = page_store.get(key);                                │  │
│  │      if (page == NULL) {                                              │  │
│  │          return error("Page not found for this schema version");      │  │
│  │      }                                                                │  │
│  │                                                                       │  │
│  │      // 如果页 LSN 不够新，需要应用更多 Redo                          │  │
│  │      if (page->lsn < req->min_lsn) {                                  │  │
│  │          page = apply_pending_redo(key, req->min_lsn);                │  │
│  │      }                                                                │  │
│  │                                                                       │  │
│  │      return page;                                                     │  │
│  │  }                                                                    │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 8.7.6 Schema 版本垃圾回收 (Schema GC)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Schema GC 机制                                            │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  旧版本 Schema 及其数据需要在安全时机回收                                    │
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │  GC 安全条件                                                          │  │
│  │  ──────────────────────────────────────────────────────────────────  │  │
│  │                                                                       │  │
│  │  Schema 版本 V 可以被 GC 的条件:                                      │  │
│  │                                                                       │  │
│  │  1. V.drop_lsn != 0  (已被删除/替代)                                 │  │
│  │                                                                       │  │
│  │  2. 所有节点 (RW + 所有 RO) 满足:                                    │  │
│  │     min_active_snapshot_lsn > V.drop_lsn                              │  │
│  │     (没有活跃事务的 snapshot 能看到这个版本)                          │  │
│  │                                                                       │  │
│  │  ┌─────────────────────────────────────────────────────────────────┐ │  │
│  │  │  LSN 时间线:                                                     │ │  │
│  │  │                                                                  │ │  │
│  │  │  ────────┬───────────┬───────────┬─────────────────────►        │ │  │
│  │  │          │           │           │                               │ │  │
│  │  │      V.create    V.drop     min_active                          │ │  │
│  │  │         │           │        snapshot                            │ │  │
│  │  │         │           │           │                                │ │  │
│  │  │    版本V生效     版本V删除   所有活跃事务                        │ │  │
│  │  │                              的最小快照                          │ │  │
│  │  │                                                                  │ │  │
│  │  │    当 min_active_snapshot > V.drop 时，V 可以被 GC              │ │  │
│  │  │                                                                  │ │  │
│  │  └─────────────────────────────────────────────────────────────────┘ │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │  GC 流程                                                              │  │
│  │  ──────────────────────────────────────────────────────────────────  │  │
│  │                                                                       │  │
│  │  // 后台 Schema GC 线程                                               │  │
│  │  void schema_gc_thread() {                                            │  │
│  │      while (running) {                                                │  │
│  │          // 1. 收集所有节点的最小活跃快照 LSN                         │  │
│  │          uint64_t min_lsn = get_cluster_min_active_snapshot_lsn();    │  │
│  │                                                                       │  │
│  │          // 2. 遍历所有已删除的 schema 版本                           │  │
│  │          for (v in schema_versions where v.drop_lsn != 0) {           │  │
│  │              if (v.drop_lsn < min_lsn) {                              │  │
│  │                  // 3. 安全删除该版本的所有数据                       │  │
│  │                  storage_layer.delete_space(v.space_id,               │  │
│  │                                             v.schema_version);        │  │
│  │                  schema_versions.remove(v);                           │  │
│  │                  log("GC schema version %d of table %s",              │  │
│  │                      v.schema_version, v.table_name);                 │  │
│  │              }                                                        │  │
│  │          }                                                            │  │
│  │                                                                       │  │
│  │          sleep(GC_INTERVAL);  // 如 10 秒                             │  │
│  │      }                                                                │  │
│  │  }                                                                    │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │  活跃快照追踪                                                         │  │
│  │  ──────────────────────────────────────────────────────────────────  │  │
│  │                                                                       │  │
│  │  每个节点维护:                                                        │  │
│  │                                                                       │  │
│  │  struct ActiveSnapshotTracker {                                       │  │
│  │      // 所有活跃查询的 snapshot LSN (最小堆)                         │  │
│  │      MinHeap<uint64_t> active_snapshots;                              │  │
│  │                                                                       │  │
│  │      void on_query_start(uint64_t snapshot_lsn) {                     │  │
│  │          active_snapshots.push(snapshot_lsn);                         │  │
│  │      }                                                                │  │
│  │                                                                       │  │
│  │      void on_query_end(uint64_t snapshot_lsn) {                       │  │
│  │          active_snapshots.remove(snapshot_lsn);                       │  │
│  │      }                                                                │  │
│  │                                                                       │  │
│  │      uint64_t get_min_active_snapshot() {                             │  │
│  │          if (active_snapshots.empty()) {                              │  │
│  │              return current_lsn;  // 无活跃查询                       │  │
│  │          }                                                            │  │
│  │          return active_snapshots.top();                               │  │
│  │      }                                                                │  │
│  │  };                                                                   │  │
│  │                                                                       │  │
│  │  // 集群级别汇总                                                      │  │
│  │  uint64_t get_cluster_min_active_snapshot_lsn() {                     │  │
│  │      uint64_t min_lsn = UINT64_MAX;                                   │  │
│  │      min_lsn = min(min_lsn, rw_node.get_min_active_snapshot());       │  │
│  │      for (ro in ro_nodes) {                                           │  │
│  │          min_lsn = min(min_lsn, ro.get_min_active_snapshot());        │  │
│  │      }                                                                │  │
│  │      return min_lsn;                                                  │  │
│  │  }                                                                    │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  Schema MVCC 的额外优势:                                                    │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │                                                                       │  │
│  │  1. 支持 Online DDL 的语义                                           │  │
│  │     - ALTER TABLE 期间，旧查询继续用旧 schema                        │  │
│  │     - 新查询可以选择等待或使用旧版本                                 │  │
│  │                                                                       │  │
│  │  2. 支持 DDL 回滚                                                    │  │
│  │     - DDL 失败时，旧版本仍然完整                                     │  │
│  │     - 可以安全回滚到旧版本                                           │  │
│  │                                                                       │  │
│  │  3. 支持时间点查询 (Point-in-Time Query)                             │  │
│  │     - 可以查询历史某个时间点的 schema 状态                           │  │
│  │     - 对审计和数据恢复有帮助                                         │  │
│  │                                                                       │  │
│  │  4. 更好的 RO 扩展性                                                 │  │
│  │     - RO 节点不会因为 DDL 而影响吞吐                                 │  │
│  │     - 特别适合读密集型负载                                           │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  空间开销控制:                                                              │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │                                                                       │  │
│  │  1. 快照水位推进: 长查询完成后及时释放 snapshot                      │  │
│  │  2. Schema GC 周期: 可配置 (如 10秒)，及时回收                       │  │
│  │  3. 保留时间上限: 配置最大保留时间，超时强制 GC                      │  │
│  │     (此时旧查询会报错，但可控)                                       │  │
│  │  4. 监控告警: 监控多版本数量，异常时告警                             │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

#### 8.7.9 故障处理

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Schema MVCC 故障场景处理                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  场景 1: 长查询导致 Schema 版本堆积                                         │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │                                                                       │  │
│  │  问题: 某查询 snapshot_lsn 太旧，阻止 Schema GC                       │  │
│  │                                                                       │  │
│  │  处理:                                                                │  │
│  │  1. 监控 schema 版本数量和最老 snapshot                               │  │
│  │  2. 当版本数量超过阈值时告警                                         │  │
│  │  3. 可配置强制 GC 策略:                                              │  │
│  │     - 超过 max_schema_versions (如 100) 时                           │  │
│  │     - 超过 max_schema_age (如 1 小时) 时                             │  │
│  │     - 强制 kill 最老的查询，推进 GC                                  │  │
│  │                                                                       │  │
│  │  // 配置示例                                                          │  │
│  │  schema_mvcc_max_versions = 100                                      │  │
│  │  schema_mvcc_max_age_seconds = 3600                                  │  │
│  │  schema_mvcc_force_gc_policy = "kill_oldest_query"                   │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  场景 2: 查询访问已 GC 的 Schema 版本                                       │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │                                                                       │  │
│  │  错误: ReadPage(schema_v=1001) 返回 SCHEMA_VERSION_NOT_FOUND         │  │
│  │                                                                       │  │
│  │  处理:                                                                │  │
│  │  1. 查询检测到 schema 版本已过期                                     │  │
│  │  2. 返回错误给客户端:                                                │  │
│  │     "Snapshot too old, schema version has been garbage collected"    │  │
│  │  3. 客户端重试即可 (使用新 snapshot)                                 │  │
│  │                                                                       │  │
│  │  预防:                                                                │  │
│  │  • 合理设置 GC 策略，保留足够长时间                                  │  │
│  │  • 监控长查询，及时告警                                              │  │
│  │  • 对于批量作业，分批提交而非超长事务                                │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  场景 3: RO Buffer Pool 中有多版本页                                        │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │                                                                       │  │
│  │  Schema MVCC 下的 Buffer Pool 管理:                                   │  │
│  │                                                                       │  │
│  │  // Buffer Pool Key 包含 schema_version                              │  │
│  │  struct BufferPageKey {                                               │  │
│  │      uint32_t space_id;                                               │  │
│  │      uint64_t schema_version;                                         │  │
│  │      uint32_t page_no;                                                │  │
│  │  };                                                                   │  │
│  │                                                                       │  │
│  │  // 不同版本的页可以同时存在于 Buffer Pool                            │  │
│  │  // 当版本被 GC 时，相关页也需要清理                                  │  │
│  │  void on_schema_version_gc(uint32_t space_id, uint64_t schema_v) {    │  │
│  │      buf_pool_invalidate_by_schema_version(space_id, schema_v);       │  │
│  │  }                                                                    │  │
│  │                                                                       │  │
│  │  优化:                                                                │  │
│  │  • LRU 淘汰时优先淘汰旧版本的页                                      │  │
│  │  • 可以设置每个版本的缓存上限                                        │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  场景 4: RW Failover                                                        │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │                                                                       │  │
│  │  RW Failover 时的 Schema MVCC 处理:                                   │  │
│  │                                                                       │  │
│  │  1. 新 RW 从存储层获取:                                              │  │
│  │     - max_durable_lsn                                                │  │
│  │     - 当前所有活跃的 schema 版本                                     │  │
│  │     - 当前最大的 schema_version 号                                   │  │
│  │                                                                       │  │
│  │  2. 新 RW 恢复到 max_durable_lsn                                     │  │
│  │                                                                       │  │
│  │  3. 新 RW 创建表时:                                                  │  │
│  │     - 从存储层获取新的 schema_version (全局递增)                     │  │
│  │     - 保证不会与旧 RW 的版本冲突                                     │  │
│  │                                                                       │  │
│  │  4. RO 节点无感知:                                                   │  │
│  │     - RO 继续按 snapshot_lsn 读取对应版本                            │  │
│  │     - 新 RW 的 DDL 会产生新版本，RO 逐渐看到                         │  │
│  │                                                                       │  │
│  │  一致性保证:                                                          │  │
│  │  • schema_version 全局递增，由存储层分配                             │  │
│  │  • Failover 不会导致版本混乱                                         │  │
│  │  • 正在进行的查询可以继续完成                                        │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│  场景 5: 存储层故障恢复                                                     │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │                                                                       │  │
│  │  存储层需要持久化的 Schema MVCC 元数据:                               │  │
│  │                                                                       │  │
│  │  1. Schema Version Table                                              │  │
│  │     - 所有活跃和待 GC 的 schema 版本                                 │  │
│  │     - create_lsn, drop_lsn                                           │  │
│  │                                                                       │  │
│  │  2. Schema Version → Page 映射                                       │  │
│  │     - 每个版本的所有页                                               │  │
│  │                                                                       │  │
│  │  3. 集群 Snapshot 水位                                               │  │
│  │     - 各节点的 min_active_snapshot                                   │  │
│  │     - 用于 GC 判断                                                   │  │
│  │                                                                       │  │
│  │  恢复流程:                                                            │  │
│  │  1. 重建 Schema Version Table (从 Redo Log)                          │  │
│  │  2. 重建 Page Index (从 Redo Log)                                    │  │
│  │  3. 保守 GC: 恢复后延迟 GC，等待节点重新上报 snapshot                │  │
│  │                                                                       │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

┌─────────────────────────────────────────────────────────────────────────────┐
│                    三种实现方案对比                                          │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  方案 1: 完全冗余 (不推荐)                                                   │
│  ─────────────────────────────────────────────────────────────────────────  │
│                                                                             │
│  schema_v=1001        schema_v=1002                                         │
│  ┌────────────┐       ┌────────────┐                                        │
│  │ Page 0     │       │ Page 0  *  │  ← 完整复制所有页                      │
│  │ Page 1     │       │ Page 1     │                                        │
│  │ Page 2     │       │ Page 2  *  │                                        │
│  │ ...        │       │ ...        │                                        │
│  │ Page N     │       │ Page N     │                                        │
│  └────────────┘       └────────────┘                                        │
│                                                                             │
│  问题: 表 100GB → DDL 后变成 200GB，完全不可行                               │
│                                                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  方案 2: Copy-on-Write (COW) - 推荐用于 ALTER DDL                            │
│  ─────────────────────────────────────────────────────────────────────────  │
│                                                                             │
│  核心思想: 只有被修改的页才会复制，未修改的页共享底层存储                    │
│                                                                             │
│  schema_v=1001                   schema_v=1002                              │
│  ┌────────────┐                  ┌────────────┐                             │
│  │ Page 0 ────┼──────────────────┼─→ 共享     │  未修改，共享同一物理块     │
│  │ Page 1 ────┼──────────────────┼─→ 共享     │                             │
│  │ Page 2     │                  │ Page 2'    │  DDL 修改了 Page 2          │
│  │ Page 3 ────┼──────────────────┼─→ 共享     │                             │
│  │ Page 4     │                  │ Page 4'    │  DDL 修改了 Page 4          │
│  └────────────┘                  └────────────┘                             │
│                                                                             │
│  空间开销: 只有 Δ (被修改的页) 需要额外空间                                  │
│                                                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  方案 3: 基于 Redo 的按需重建 (Aurora 风格) - 推荐用于读取历史版本           │
│  ─────────────────────────────────────────────────────────────────────────  │
│                                                                             │
│  核心思想: 存储层只保存最新版本 + Redo Log                                   │
│            需要旧版本时，从 Redo 逆向重建                                    │
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │                                                                       │   │
│  │  存储层数据结构:                                                      │   │
│  │                                                                       │   │
│  │  Page Store (只存最新版本):                                           │   │
│  │  ────────────────────────                                             │   │
│  │  (space_id, page_no) → { latest_page_data, latest_lsn }              │   │
│  │                                                                       │   │
│  │  Redo Log Store (保留历史):                                           │   │
│  │  ─────────────────────────                                            │   │
│  │  LSN range: [min_retained_lsn, current_lsn]                          │   │
│  │  保留足够长时间的 Redo (如 1 小时)                                    │   │
│  │                                                                       │   │
│  │  Schema Version Table:                                                │   │
│  │  ─────────────────────                                                │   │
│  │  (space_id, schema_v) → { create_lsn, drop_lsn }                     │   │
│  │                                                                       │   │
│  └──────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  优点:                                                                      │
│  • 无额外存储开销 (只有 Redo Log，但本来就要保留)                           │
│  • 简单，与 Aurora 架构一致                                                 │
│                                                                             │
│  缺点:                                                                      │
│  • 读取旧版本需要计算 (但通常是短时间的过渡期)                              │
│  • 需要保留足够长的 Redo Log                                                │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### D.2 COW 实现细节

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Copy-on-Write 实现                                        │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  Page Index 结构:                                                            │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │                                                                       │   │
│  │  struct PageIndexEntry {                                              │   │
│  │      LBA      lba;             // 物理块地址                          │   │
│  │      uint64_t page_lsn;        // 页的 LSN                           │   │
│  │      bool     is_shared;       // 是否与其他版本共享                  │   │
│  │      uint64_t shared_with;     // 如果共享，指向源版本                │   │
│  │  };                                                                   │   │
│  │                                                                       │   │
│  │  // 索引: (space_id, schema_version, page_no) → PageIndexEntry       │   │
│  │  PageIndex page_index;                                                │   │
│  │                                                                       │   │
│  └──────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  DDL CREATE 时的 COW 逻辑:                                                   │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │                                                                       │   │
│  │  void on_ddl_create_new_version(uint32_t space_id,                    │   │
│  │                                 uint64_t old_v,                       │   │
│  │                                 uint64_t new_v,                       │   │
│  │                                 DDLType  ddl_type) {                  │   │
│  │                                                                       │   │
│  │      if (ddl_type == DDL_DROP_CREATE) {                               │   │
│  │          // DROP + CREATE: 新版本完全独立，旧版本等待 GC              │   │
│  │          // 新版本从空开始，不需要做任何事                            │   │
│  │          return;                                                      │   │
│  │      }                                                                │   │
│  │                                                                       │   │
│  │      if (ddl_type == DDL_ALTER_INSTANT) {                             │   │
│  │          // Instant DDL (如 ADD COLUMN): 只修改元数据，所有页共享     │   │
│  │          for (page_no in all_pages(space_id, old_v)) {                │   │
│  │              PageIndexEntry old_entry = page_index.get(               │   │
│  │                  space_id, old_v, page_no);                           │   │
│  │                                                                       │   │
│  │              // 新版本指向旧版本的物理块                              │   │
│  │              page_index.put(space_id, new_v, page_no, {               │   │
│  │                  .lba = old_entry.lba,                                │   │
│  │                  .page_lsn = old_entry.page_lsn,                      │   │
│  │                  .is_shared = true,                                   │   │
│  │                  .shared_with = old_v                                 │   │
│  │              });                                                      │   │
│  │          }                                                            │   │
│  │      }                                                                │   │
│  │                                                                       │   │
│  │      if (ddl_type == DDL_ALTER_REBUILD) {                             │   │
│  │          // 需要重建的 ALTER: 边重建边 COW                            │   │
│  │          // 初始时所有页共享，修改时才复制                            │   │
│  │          for (page_no in all_pages(space_id, old_v)) {                │   │
│  │              PageIndexEntry old_entry = page_index.get(               │   │
│  │                  space_id, old_v, page_no);                           │   │
│  │                                                                       │   │
│  │              page_index.put(space_id, new_v, page_no, {               │   │
│  │                  .lba = old_entry.lba,                                │   │
│  │                  .page_lsn = old_entry.page_lsn,                      │   │
│  │                  .is_shared = true,                                   │   │
│  │                  .shared_with = old_v                                 │   │
│  │              });                                                      │   │
│  │          }                                                            │   │
│  │          // 后续写入时会触发 COW                                      │   │
│  │      }                                                                │   │
│  │  }                                                                    │   │
│  │                                                                       │   │
│  └──────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  写入时的 COW 触发:                                                          │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │                                                                       │   │
│  │  void write_page(uint32_t space_id, uint64_t schema_v,                │   │
│  │                  uint32_t page_no, Page* new_data) {                  │   │
│  │                                                                       │   │
│  │      PageIndexEntry entry = page_index.get(space_id, schema_v,        │   │
│  │                                            page_no);                  │   │
│  │                                                                       │   │
│  │      if (entry.is_shared) {                                           │   │
│  │          // COW: 分配新的物理块                                       │   │
│  │          LBA new_lba = block_allocator.alloc();                       │   │
│  │          disk.write(new_lba, new_data);                               │   │
│  │                                                                       │   │
│  │          // 更新索引，指向新块，不再共享                              │   │
│  │          page_index.put(space_id, schema_v, page_no, {                │   │
│  │              .lba = new_lba,                                          │   │
│  │              .page_lsn = new_data->lsn,                               │   │
│  │              .is_shared = false,                                      │   │
│  │              .shared_with = 0                                         │   │
│  │          });                                                          │   │
│  │      } else {                                                         │   │
│  │          // 直接覆盖写                                                │   │
│  │          disk.write(entry.lba, new_data);                             │   │
│  │          entry.page_lsn = new_data->lsn;                              │   │
│  │          page_index.put(space_id, schema_v, page_no, entry);          │   │
│  │      }                                                                │   │
│  │  }                                                                    │   │
│  │                                                                       │   │
│  └──────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  读取时解引用共享:                                                           │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │                                                                       │   │
│  │  Page* read_page(uint32_t space_id, uint64_t schema_v,                │   │
│  │                  uint32_t page_no) {                                  │   │
│  │                                                                       │   │
│  │      PageIndexEntry entry = page_index.get(space_id, schema_v,        │   │
│  │                                            page_no);                  │   │
│  │      if (entry == NULL) {                                             │   │
│  │          return NULL;  // 页不存在                                    │   │
│  │      }                                                                │   │
│  │                                                                       │   │
│  │      if (entry.is_shared) {                                           │   │
│  │          // 递归到源版本 (通常只有一层)                               │   │
│  │          return read_page(space_id, entry.shared_with, page_no);      │   │
│  │      }                                                                │   │
│  │                                                                       │   │
│  │      return disk.read(entry.lba);                                     │   │
│  │  }                                                                    │   │
│  │                                                                       │   │
│  └──────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### D.3 基于 Redo 的按需重建

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Redo 按需重建实现                                         │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  适用场景: 读取历史版本的页 (旧查询需要看到旧数据)                           │
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │                                                                       │   │
│  │  Page* read_page_at_lsn(uint32_t space_id,                            │   │
│  │                         uint64_t schema_v,                            │   │
│  │                         uint32_t page_no,                             │   │
│  │                         uint64_t required_lsn) {                      │   │
│  │                                                                       │   │
│  │      // 1. 获取该 schema 版本信息                                     │   │
│  │      SchemaInfo* schema_info = schema_table.get(space_id, schema_v);  │   │
│  │      if (schema_info == NULL) {                                       │   │
│  │          return error("Schema version not found");                    │   │
│  │      }                                                                │   │
│  │                                                                       │   │
│  │      // 2. 检查 LSN 是否在有效范围内                                  │   │
│  │      if (required_lsn < schema_info->create_lsn) {                    │   │
│  │          return error("LSN before schema creation");                  │   │
│  │      }                                                                │   │
│  │      if (schema_info->drop_lsn != 0 &&                                │   │
│  │          required_lsn >= schema_info->drop_lsn) {                     │   │
│  │          return error("LSN after schema drop");                       │   │
│  │      }                                                                │   │
│  │                                                                       │   │
│  │      // 3. 读取当前版本的页                                           │   │
│  │      Page* current_page = page_store.get(space_id, page_no);          │   │
│  │      if (current_page == NULL) {                                      │   │
│  │          return error("Page not found");                              │   │
│  │      }                                                                │   │
│  │                                                                       │   │
│  │      // 4. 如果当前页 LSN <= 需要的 LSN，直接返回                     │   │
│  │      if (current_page->lsn <= required_lsn) {                         │   │
│  │          return current_page;                                         │   │
│  │      }                                                                │   │
│  │                                                                       │   │
│  │      // 5. 需要重建旧版本: 获取相关的 Redo 记录                       │   │
│  │      vector<RedoRecord> redo_records = redo_store.get_range(          │   │
│  │          required_lsn + 1,      // from: required_lsn 之后            │   │
│  │          current_page->lsn,     // to: 当前页 LSN                     │   │
│  │          space_id,                                                    │   │
│  │          page_no                                                      │   │
│  │      );                                                               │   │
│  │                                                                       │   │
│  │      // 6. 逆序遍历，undo 每个修改                                    │   │
│  │      Page* page = clone(current_page);                                │   │
│  │      for (int i = redo_records.size() - 1; i >= 0; i--) {             │   │
│  │          page = undo_redo(page, redo_records[i]);                     │   │
│  │      }                                                                │   │
│  │                                                                       │   │
│  │      return page;                                                     │   │
│  │  }                                                                    │   │
│  │                                                                       │   │
│  │  // Undo 单条 Redo 记录                                               │   │
│  │  Page* undo_redo(Page* page, RedoRecord* redo) {                      │   │
│  │      // 方案 A: Redo 记录包含 before_image                            │   │
│  │      if (redo->has_before_image) {                                    │   │
│  │          apply_before_image(page, redo->before_image);                │   │
│  │          return page;                                                 │   │
│  │      }                                                                │   │
│  │                                                                       │   │
│  │      // 方案 B: 根据 Redo 类型进行逆操作                              │   │
│  │      switch (redo->type) {                                            │   │
│  │          case MLOG_REC_INSERT:                                        │   │
│  │              // 插入 → 删除                                           │   │
│  │              undo_insert(page, redo);                                 │   │
│  │              break;                                                   │   │
│  │          case MLOG_REC_DELETE:                                        │   │
│  │              // 删除 → 重新插入 (需要 before_image)                   │   │
│  │              undo_delete(page, redo);                                 │   │
│  │              break;                                                   │   │
│  │          case MLOG_REC_UPDATE:                                        │   │
│  │              // 更新 → 恢复旧值 (需要 before_image)                   │   │
│  │              undo_update(page, redo);                                 │   │
│  │              break;                                                   │   │
│  │          // ... 其他类型                                              │   │
│  │      }                                                                │   │
│  │      return page;                                                     │   │
│  │  }                                                                    │   │
│  │                                                                       │   │
│  └──────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  Redo 记录格式 (支持 undo):                                                  │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │                                                                       │   │
│  │  struct RedoRecord {                                                  │   │
│  │      uint8_t  type;             // Redo 类型                         │   │
│  │      uint64_t lsn;              // 日志序列号                        │   │
│  │      uint32_t space_id;         // 表空间 ID                         │   │
│  │      uint64_t schema_version;   // Schema 版本                       │   │
│  │      uint32_t page_no;          // 页号                              │   │
│  │      uint16_t offset;           // 页内偏移                          │   │
│  │                                                                       │   │
│  │      // 用于 undo 的字段                                             │   │
│  │      bool     has_before_image; // 是否包含修改前数据                │   │
│  │      bytes    before_image;     // 修改前数据 (可选)                 │   │
│  │      bytes    after_image;      // 修改后数据                        │   │
│  │  };                                                                   │   │
│  │                                                                       │   │
│  │  // 注: before_image 会增加 Redo 日志大小                             │   │
│  │  // 可以选择性记录 (如只对 UPDATE/DELETE 记录)                        │   │
│  │                                                                       │   │
│  └──────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### D.4 推荐混合策略

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    推荐实现: 混合策略                                        │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  根据 DDL 类型选择不同策略:                                                  │
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │  DDL 类型               │  策略              │  空间开销              │   │
│  ├──────────────────────────────────────────────────────────────────────┤   │
│  │                                                                       │   │
│  │  DROP + CREATE          │  独立存储          │  无 (旧版本等GC)      │   │
│  │  (同名表重建)           │  (不共享)          │                        │   │
│  │                                                                       │   │
│  │  ALTER (Instant DDL)    │  COW 共享          │  近乎为 0             │   │
│  │  如 ADD COLUMN          │  (只改元数据)      │  (所有页共享)          │   │
│  │                                                                       │   │
│  │  ALTER (需要重建)       │  COW + Redo        │  Δ + Redo 大小        │   │
│  │  如 MODIFY COLUMN TYPE  │                    │                        │   │

### D.6 总结

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Schema MVCC 存储实现总结                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  Q: 三元组索引是否需要完全冗余数据？                                         │
│  A: 不需要。                                                                 │
│                                                                             │
│  实现要点:                                                                   │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │                                                                       │   │
│  │  1. DROP + CREATE: 新旧版本使用不同 space_id，完全独立                │   │
│  │     - 无冗余，旧版本等待 GC 释放                                     │   │
│  │                                                                       │   │
│  │  2. ALTER (Instant): 使用 COW，所有页指向同一物理块                  │   │
│  │     - 无冗余，只有元数据开销                                         │   │
│  │                                                                       │   │
│  │  3. ALTER (Rebuild): COW + 按需复制                                  │   │
│  │     - 只复制被修改的页，未修改的页共享                               │   │
│  │                                                                       │   │
│  │  4. 历史版本读取: 基于 Redo 按需重建                                 │   │
│  │     - 不额外存储历史版本，从最新版本 + Redo 计算                     │   │
│  │                                                                       │   │
│  └──────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  空间开销: 通常 < 10%，且是临时的 (GC 后恢复)                               │
│  读取性能: 最新版本 O(1)，历史版本需要 Redo 计算 (但持续时间短)              │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### E.5 元数据服务的核心职责

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    元数据服务核心职责                                        │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  职责 1: 表空间管理 (替代文件系统的目录+文件操作)                            │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │                                                                       │   │
│  │  // 创建表空间 (替代 open + O_CREAT)                                  │   │
│  │  CreateTablespaceResponse create_tablespace(                          │   │
│  │      string db_name,           // 数据库名                           │   │
│  │      string table_name,        // 表名                               │   │
│  │      uint64 initial_size       // 初始大小 (页数)                    │   │
│  │  ) {                                                                  │   │
│  │      space_id = allocate_space_id();                                  │   │
│  │      schema_version = allocate_schema_version();                      │   │
│  │                                                                       │   │
│  │      // 注册到表空间注册表                                            │   │
│  │      tablespace_registry.put(space_id, schema_version, {              │   │
│  │          db_name, table_name, state: ACTIVE, create_lsn              │   │
│  │      });                                                              │   │
│  │                                                                       │   │
│  │      // 预分配初始块                                                  │   │
│  │      for (page_no = 0; page_no < initial_size; page_no++) {           │   │
│  │          lba = block_allocator.alloc();                               │   │
│  │          page_index.put((space_id, schema_version, page_no), lba);    │   │
│  │      }                                                                │   │
│  │                                                                       │   │
│  │      return { space_id, schema_version };                             │   │
│  │  }                                                                    │   │
│  │                                                                       │   │
│  │  // 删除表空间 (替代 unlink)                                          │   │
│  │  void drop_tablespace(uint32 space_id, uint64 schema_version) {       │   │
│  │      // 标记为 dropped，不立即删除 (Schema MVCC)                      │   │
│  │      tablespace_registry.mark_dropped(space_id, schema_version,       │   │
│  │                                       drop_lsn);                      │   │
│  │      // 等待 Schema GC 后真正释放块                                   │   │
│  │  }                                                                    │   │
│  │                                                                       │   │
│  │  // 查找表空间 (替代 stat/open)                                       │   │
│  │  TablespaceInfo lookup_tablespace(string db_name, string table_name,  │   │
│  │                                   uint64 snapshot_lsn) {              │   │
│  │      // 根据 snapshot_lsn 找到可见的 schema 版本                      │   │
│  │      return tablespace_registry.find_visible(db_name, table_name,     │   │
│  │                                              snapshot_lsn);           │   │
│  │  }                                                                    │   │
│  │                                                                       │   │
│  └──────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  职责 2: 页地址映射 (替代文件偏移计算)                                       │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │                                                                       │   │
│  │  传统方式:                                                            │   │
│  │  ───────────                                                          │   │
│  │  文件偏移 = page_no * 16384                                          │   │
│  │  pread(fd, buf, 16384, offset)                                       │   │
│  │                                                                       │   │
│  │  元数据服务方式:                                                      │   │
│  │  ─────────────────                                                    │   │
│  │  LBA lookup_page(uint32 space_id, uint64 schema_v, uint32 page_no) { │   │
│  │      entry = page_index.get((space_id, schema_v, page_no));           │   │
│  │      if (entry == NULL) {                                             │   │
│  │          return NOT_FOUND;                                            │   │
│  │      }                                                                │   │
│  │      return entry.lba;                                                │   │
│  │  }                                                                    │   │
│  │                                                                       │   │
│  │  // 然后直接读块存储                                                  │   │
│  │  block_storage.read(lba);                                             │   │
│  │                                                                       │   │
│  │  关键区别:                                                            │   │
│  │  • 传统: page_no → file_offset (固定公式)                            │   │
│  │  • 新方式: page_no → LBA (通过索引查找，支持重映射)                  │   │
│  │                                                                       │   │
│  └──────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  职责 3: 块空间分配 (替代文件系统 + FSP_HDR)                                │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │                                                                       │   │
│  │  // 为表空间分配新页                                                  │   │
│  │  LBA allocate_page(uint32 space_id, uint64 schema_v, uint32 page_no) {│   │
│  │      lba = block_allocator.alloc();                                   │   │
│  │      page_index.put((space_id, schema_v, page_no), { lba, 0 });       │   │
│  │      return lba;                                                      │   │
│  │  }                                                                    │   │
│  │                                                                       │   │
│  │  // 释放页 (Schema GC 时调用)                                         │   │
│  │  void free_page(uint32 space_id, uint64 schema_v, uint32 page_no) {   │   │
│  │      entry = page_index.remove((space_id, schema_v, page_no));        │   │
│  │      if (entry != NULL && !entry.is_shared) {                         │   │
│  │          block_allocator.free(entry.lba);                             │   │
│  │      }                                                                │   │
│  │  }                                                                    │   │
│  │                                                                       │   │
│  │  抛弃的 InnoDB 原生概念:                                              │   │
│  │  • FSP_HDR (表空间头) - 不需要，元数据服务管理空间                   │   │
│  │  • Extent Descriptor - 不需要，块分配器直接管理                      │   │
│  │  • INODE Page (段描述符) - 不需要，简化为页级别管理                  │   │
│  │  • 文件扩展 - 不需要，按需分配块即可                                 │   │
│  │                                                                       │   │
│  └──────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  职责 4: LSN 语义支持 (文件系统没有的能力)                                   │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │                                                                       │   │
│  │  // 读取特定 LSN 版本的页                                             │   │
│  │  Page read_page_at_lsn(uint32 space_id, uint64 schema_v,              │   │
│  │                        uint32 page_no, uint64 required_lsn) {         │   │
│  │      entry = page_index.get((space_id, schema_v, page_no));           │   │
│  │      page = block_storage.read(entry.lba);                            │   │
│  │                                                                       │   │
│  │      if (page.lsn < required_lsn) {                                   │   │
│  │          // 页还不够新，需要应用更多 Redo                             │   │
│  │          page = apply_redo_until(page, required_lsn);                 │   │
│  │      } else if (page.lsn > required_lsn) {                            │   │
│  │          // 页太新，需要读取历史版本 (逆向 Redo)                      │   │
│  │          page = reconstruct_page_at_lsn(page, required_lsn);          │   │
│  │      }                                                                │   │
│  │                                                                       │   │
│  │      return page;                                                     │   │
│  │  }                                                                    │   │
│  │                                                                       │   │
│  │  这是文件系统无法提供的能力!                                          │   │
│  │  元数据服务理解 LSN，可以提供时间点一致性读取                         │   │
│  │                                                                       │   │
│  └──────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### E.6 不需要传统文件系统功能的原因

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    为什么不需要完整的文件系统？                               │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │                                                                       │   │

│  │  ──────────────────────────────────────────────────────────────────  │   │

│  │  支持 atime/mtime/ctime         │  不需要 (可选)                      │   │
│  │  支持任意偏移读写               │  只需要页对齐的读写 (16KB 单位)     │   │
│  │                                                                       │   │

│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐   │
│  │                                                                       │   │
│  │  2. InnoDB 已经有自己的空间管理                                       │   │
│  │  ──────────────────────────────────────────────────────────────────  │   │
│  │                                                                       │   │
│  │  传统 InnoDB 在 .ibd 文件内部已经有完整的空间管理:                    │   │
│  │  • FSP_HDR 管理 extent 分配                                          │   │
│  │  • INODE 管理段                                                       │   │
│  │  • 页内有 free space 管理                                            │   │
│  │                                                                       │   │
│  │  这些在存算分离架构中被 元数据服务 替代:                              │   │
│  │  • 不需要在文件内维护空间信息                                        │   │
│  │  • 元数据服务直接管理 页→块 映射                                     │   │

│  │                                                                       │   │

│                                                                             │
│  ┌──────────────────────────────────────────────────────────────────────┐   │

│  │  ──────────────────────────────────────────────────────────────────  │   │
│  │                                                                       │   │
│  │  需求                          │  文件系统  │  元数据服务             │   │

│  │  按 LSN 读取页                  │  不支持    │  支持                   │   │
│  │  Schema 多版本                  │  不支持    │  支持                   │   │
│  │  页级别的多版本                 │  不支持    │  支持                   │   │
│  │  Redo 应用到页                  │  不理解    │  深度集成               │   │
│  │  跨节点一致性                   │  单机      │  分布式                 │   │
│  │                                                                       │   │
│  └──────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
